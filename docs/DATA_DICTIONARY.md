# Data dictionary: synthetic e-commerce dataset

Generated by `python generate_data.py` (default: 200 customers, seed 42). Every file is in
`data/dataset/` (CSV) and in `data/shop.db` (SQLite). The data is **synthetic**: customers,
brands and products are fictional. Behaviour comes from hidden personas (`config/personas.yaml`),
products and promotions from `config/catalog.yaml`.

"Amazon / GA4 name" gives the closest public Amazon metric or Google Analytics 4 event,
following `docs/amazon_research.md`.

| File | Rows (200 customers) | What it is |
|---|---:|---|
| `customers.csv` | 200 | Profile, membership, consent and the hidden persona |
| `products.csv` | 105 | Catalog: 7 categories × 5 product types × 3 fictional brands |
| `promotions.csv` | ~27 | Store campaigns over the last year (one every 14 days) |
| `orders.csv` | ~5,000 | Every order over the customer's whole tenure |
| `order_items.csv` | ~4,600 | Products in each order, **last 365 days only** |
| `events.csv` | ~430,000 | Every browsing event in the last 365 days |
| `loyalty_tx.csv` | ~5,700 | Points earned and redeemed |
| `market_basket.csv` | ~140 | Product types bought together (like Amazon's Market Basket report) |
| `customer_features.csv` | 200 | One row per customer: every feature, the engine's scores and segment |

## customers.csv

| Column | Meaning | Amazon / GA4 name |
|---|---|---|
| customer_id | Unique ID (U0001…) | USER_ID (Personalize) |
| name, city | Fictional name and city | – |
| signup_date | Account creation time | – |
| opted_in | Agreed to receive offers at all (rule R1) | – |
| consent_email / sms / push / whatsapp | Channel-level consent | – |

| signup_channel | organic, search_ad, social, referral, marketplace | traffic source |
| preferred_device | mobile_app, mobile_web, desktop | device category |
| persona | **Hidden ground truth**, for testing only; never used by the engine | – |
| points_mult | Loyalty points multiplier (VIP perk) | – |

## events.csv: one row per event (GA4 naming)

| event_name | When it happens | Amazon equivalent |
|---|---|---|
| session_start | A visit starts | Sessions (Business Reports) |
| search | Customer searches (search_term) | search queries (Search Query Performance) |
| view_item_list | A product is **shown** in search results or a category page (one row per product, with position) | **Impressions** |
| select_item | A shown product is **clicked** | **Clicks** |
| view_item | Product page view | **Page Views / detail page views** (glance views) |
| add_to_wishlist | Saved to wishlist | Wish List |
| follow_brand | Customer follows a brand | **Brand Followers** |
| not_interested | Customer hides a product | "Not interested" (Improve Your Recommendations) |
| view_promotion / select_promotion | Saw / clicked the store campaign banner | promotion impressions / clicks |
| add_to_cart / remove_from_cart | Cart changes | **Cart Adds** |
| view_cart, begin_checkout | Checkout steps | – |
| purchase | Order placed (transaction_id = order_id) | **Purchases**, Units Ordered |
| write_review | Review with a 1–5 star rating, days after a purchase | reviews / ratings |
| refund | Order returned | returns / refunds |

| Column | Meaning |
|---|---|
| event_id, customer_id, session_id, event_time | Identity and time (session_id empty for reviews and refunds) |
| product_id, brand, category, price | Product involved (if any) |
| quantity, value | Units and INR value (cart and order events) |
| search_term | For `search` |
| item_list_name, position | For impressions and clicks: search_results or category_page, rank 1–8 |
| promotion_id, coupon | For promotion events, checkout and purchase |
| transaction_id | Order ID for purchase, review and refund |
| rating | 1–5 for write_review |
| device | mobile_app, mobile_web, desktop |

## market_basket.csv

| Column | Meaning |
|---|---|
| item_type, bought_with | Product type A and product type B |
| orders_together | Orders containing both |
| support | Share of all orders containing both |
| confidence | Share of A's orders that also contain B |
| lift | confidence ÷ share of orders with B (above 1 means bought together more than chance) |

Orders contain products from a single category, so pairs are within the same category.

## customer_features.csv: one row per customer

### Original features (used by the rules and the AI)

| Column | Meaning |
|---|---|
| tenure_days, orders_total, recency_days, avg_gap_days, frequency_90d, aov, coupon_rate | Order history (RFM) |
| top_category | Most-bought category (or most-browsed if no orders) |
| cart_abandoned_hours_ago, abandoned_cart_value, abandoned_cart_item | Open cart (latest cart add after the last order) |
| browse_no_buy_14d | Sessions without a purchase, last 14 days |
| points_balance, points_expiring_30d, tier | Loyalty |
| days_since_discount_redeemed | For the discount cooldown (rule R10) |
| gap_ratio, churn_risk, would_buy_anyway, p_buy_7d, segment | Derived by the engine (`src/segments.py`); p_buy_7d ≈ GA4 "purchase probability" |

|---|---|---|

| wishlist_adds_90d, wishlist_open_items | Wishlist adds; wishlisted products never bought | – |
| promo_views_90d, promo_clicks_90d, promo_ctr_90d | Response to store campaigns (a deal-seeking signal) | – |
| brands_followed, followed_brands | Brand follows | Brand Followers |
| not_interested_90d | Hidden products | – |
| orders_30d / 90d / 365d, spend_365d | Recent orders and 12-month spend | – |
| unit_session_pct_90d | Orders ÷ sessions | Unit Session Percentage (conversion) |
| coupons_used_365d | Coupon orders in 12 months | coupon redemptions |
| reviews_365d, avg_rating_given | Reviews written | – |
| returns_365d, return_rate_365d | Refunded orders | returns |
| top_brand, top_brand_share | Most-bought brand and its share of items | – |
| focus_product_id / name / type / price / category | The one product the customer wants most right now (target of PRODUCT_COUPON) | – |
| focus_product_reason | Why: `in cart` > `wishlist` > `viewed` (30 days) > `popular in category` (never out of stock or a sensitive type) | – |
| focus_product_in_stock, focus_product_overstock | Stock status of the focus product (R25) | – |

| cart_item_in_stock | Whether the open cart item is in stock (R25) | – |
| replenish_due, replenish_item | Grocery/Beauty restock is due at the customer's own reorder cycle (R29) | – |
| review_due_item | Product from an order 5–30 days ago, not returned, not yet reviewed (R29) | – |
| suspected_multi_account | Duplicate-account flag (R23); always false here: needs device/address data | – |
| uplift_group | persuadable / sure_thing / lost_cause / sleeping_dog (rule of thumb, `src/segments.py`; sleeping dog = bad reactions to past offers) | uplift quadrants |
| base_segment | The segment ignoring an open cart; caps are the stricter of segment and base segment | – |
| cart_alternative_name | Similar in-stock product when the cart item is out of stock (CART_ALTERNATIVE) | – |
| margin_365d | Margin from the customer's orders over 12 months (R31 per-customer spend cap) | – |
| consent_telegram | Consent for Telegram, the real delivery channel (email/SMS/push/WhatsApp are simulated) | – |

products.csv also has `stock_units` and `overstock`. The promotions calendar runs 60 days past
the reference date (planned campaigns), for R22 and the 30-day simulation. A Diwali browsing
boost is configured in `config/catalog.yaml`; order history is unchanged so earlier results
stay reproducible. About 4% of customers have a missing city or signup channel.

### Audience flags (Amazon's published definitions, applied to this store)

| Column | Rule | Amazon audience |
|---|---|---|
| aud_brand_follower | follows at least one brand | Brand Followers |
| aud_repeat_customer | 2+ orders in 12 months | Repeat Customers |
| aud_recent_customer | ordered in the last 30 days | Recent Customers |
| aud_high_spend | top 10% of 12-month spend | High-Spend Customers |
| aud_potential_new_customer | clicked or added to cart, no order in 12 months | Potential New Customers |
| aud_cart_abandoner | added to cart in 3 months, no order in 3 months | Cart Abandoners |
| aud_views_remarketing_30d | viewed products in 30 days, no order in 30 days | Views remarketing |
| aud_one_time_customer | exactly one order ever | One-time customers |
| aud_lapsed | has ordered, but not in the last 90 days | Lapsed customers |
| new_to_brand_12m | no order in 12 months (a purchase now would be new-to-brand) | New-to-brand |
| amazon_audiences | all audience flags that apply, joined with "\|" | – |

Note: Amazon's audiences use 3–12 month windows, while the engine's own segments use shorter
ones. For example, the engine's CART_ABANDONER segment means an open cart in the last 48 hours.
So a customer can be in the engine's segment without being in Amazon's audience, or the reverse.
